## Quest briefing

### Problem

Managing dotfiles by hand is tedious. Creating symlinks is error-prone,
and keeping track of what's linked and what isn't is a mental burden. GNU
Stow does the linking but gives you no view of the current state.

![LazyDots TUI interface preview](/images/projects/lazydots/tui-preview.webp)

### What I built

- A Bubbletea/Lipgloss TUI that reads Stow-style package directories and
  shows per-file symlink state: linked, missing, or conflicting.
- One-key linking: press `space` to link or unlink an individual file.
- Safe operations: it never overwrites existing files, and only removes
  symlinks that point back into your repo.
- A first-run setup wizard and a `--no-splash` flag; installs with
  `go install`.

### Roadmap

Batch link/unlink per package, Git status and commit/push/pull from the
TUI, per-machine profiles, and a conflict-resolution UI (diff, backup,
overwrite). None of these ship yet.

## Loot (what was learned)

- The Elm architecture (via Bubbletea) is a genuinely great fit for
  terminal UIs — state, update, view, done.
- Symlink edge cases are endless: broken links, nested dirs, files that
  exist but aren't links. Safety checks earn their keep.
- Designing a tool you use daily is the fastest feedback loop there is.
